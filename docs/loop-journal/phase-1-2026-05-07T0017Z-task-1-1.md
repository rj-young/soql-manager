## Anything surprising

1. **DB clients are split across two trees, not one.** The PRD references `apps/studio/src/lib/db/clients/*` but only the *community* drivers live there (Postgres, MySQL, SQLite, SQL Server, Bedrock, BigQuery, Cockroach, Greengage, MariaDB, Redis, Redshift, TiDB). The *commercial-tier* drivers (Cassandra, ClickHouse, DuckDB, Firebird, libsql, MongoDB, Oracle, ScyllaDB, SurrealDB, Trino, SQL Anywhere) live under `apps/studio/src-commercial/backend/lib/db/clients/`. Task 1.3 needs to touch both directories. The §4 carve-out applies — these are DB drivers, not paid-feature code.

2. **`apps/studio/src/lib/db/migration/` does not exist.** PRD Task 1.4 references it. The actual migrations directory is `apps/studio/src/migration/` (one level up) and contains 80+ idempotent JS migration files plus an `ultimate/` subdirectory of paid-tier migrations. The 1.4 instruction "delete per-dialect migration code" doesn't have a target — none of the migrations are dialect-specific in this fork; they're all schema migrations for the appdb itself. Task 1.4 will need scope adjustment. Recommend treating the entire `migration/` directory as Keep, and dropping the per-dialect-migration bullet from 1.4.

3. **An `apps/studio/src/migration/ultimate/` subdirectory exists** with 2 migration files. Per PRD anti-goal §4 these are skipped — not deleted (would brick existing Ultimate users) and not extended.

4. **Telemetry surfaces aren't in the directories Task 1.1 was asked to read.** PRD §5 specifies stripping telemetry in Phase 1. Recommend Task 1.3 begins with a dedicated `rg "telemetry|analytics|posthog|mixpanel|segment|sentry"` sweep before any deletion, producing a sub-inventory. Surfaced in `docs/cleanse-inventory.md` §13 as a follow-up.

5. **Two pre-existing `xlsx` call sites worth flagging now:**
   - `apps/studio/src-commercial/entrypoints/renderer.ts` exposes `xlsx` on `window.XLSX` at startup.
   - `apps/studio/src/components/editor/ResultTable.vue` and `apps/studio/src/components/editor/QueryEditorStatusBar.vue` use it for grid → xlsx export.

   All four call sites (plus `import/formats/xlsx.ts` and `import/utils.js`) get deleted in Task 1.3, after which the `xlsx-stub` package can be removed. The stub `package.json` references `version: 0.20.3` to match upstream — yarn re-resolves cleanly when the dep itself is removed.

6. **Migrations reference the deleted clients.** Several migrations (`20220817_add_redshift_options.js`, `20221120_add_cassandra_options.js`, `20240107_add_firebird_dev_connection.js`, etc.) add dialect-specific columns to `saved_connection`. They stay (history is append-only). The columns themselves get removed by a new "drop legacy connection columns" migration in Task 1.5.

7. **Several Beekeeper Cloud / workspace surfaces are flagged ⚠️ Skip pending verification.** `CloudCredential.ts`, `CredentialsModule.ts`, `lib/cloud/*`, `LicenseKey.ts`, `LicenseModule.ts`, `components/license/*`, `components/managers/*`. Some are clearly Ultimate (License*); others may be community-shared (Cloud workspace = team sharing). Default behavior: don't touch in Phase 1. If they turn out to break the build after the cleanse, treat as a 1.7 verification finding and surface for human decision.
