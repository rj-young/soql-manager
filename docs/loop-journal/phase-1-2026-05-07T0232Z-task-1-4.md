## Anything surprising

1. **`sql-formatter` and `sql-query-identifier` survived Task 1.2 by transitive resolution.** They were removed from `apps/studio/package.json` in 1.2 but pulled back in via `@beekeeperstudio/bks-ai-shell` (and possibly `@beekeeperstudio/ui-kit`). Build worked fine because transitive packages get hoisted into `node_modules/` and Node's resolution algorithm doesn't distinguish "direct vs transitive." This is fragile — a future ai-shell version could drop the dependency and break our code without warning. Removing the call sites was the durable fix.

2. **`apps/studio/src/shared/lib/knex-*` helper directories were missed in Task 1.3.** Six directories with dialect-specific knex schema/query compilers (Oracle, DuckDB, Firebird, MySQL5_4, BigQuery, ClickHouse). Inventory should have caught them; they were inside `src/shared/lib/` which the inventory paged through more lightly than `src/lib/db/`. Recovered here. No callers remain after their deletion (their parent was `SqlGenerator.ts`, also gone).

3. **`BasicDatabaseClient.ts` had a `connectTunnel` import that survived Task 1.3.** I deleted `apps/studio/src/lib/db/tunnel.ts` but didn't strip this import. The build passed because the file isn't reached by the bundler — it's compiled into a chunk that nothing imports at runtime (factory throws NotImplemented before reaching the base class). Esbuild only flags unresolved imports for files that reach an entry point. Lesson: "build green" is not equivalent to "no dangling imports" when there are unreachable code paths. Did a complete `rg "from .*tunnel"` sweep here to confirm no other tunnel survivors.

4. **`handlerState.ts` had three more dangling imports** (`Export`, `ImportClass`, `ChildProcessWithoutNullStreams` for backup processes) — same root cause as #3. All cleaned.

5. **`SqlGenerator.ts` was structurally dead** but referenced as a type slot in `handlerState.ts`. Once that slot was removed, deleting the file was safe.

6. **Stub strategy worked well for the inert editor / base class.** Inline type aliases (`type Knex = any`) and tiny helper functions (`identify(_, _) => []`) let the source compile without the deleted packages. Phase 2 SfClient extends a much smaller base; Phase 3 SOQL editor adds proper SOQL parsing back. Until then, behavior degrades safely (no statements identified, no SQL formatted, raw text passes through).
