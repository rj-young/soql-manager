## Anything surprising

1. **Five extras vs. the PRD's anti-list.** The PRD §7 anti-list names 14 packages. The actual deletes were 40. Extras came from the Task 1.1 inventory (`@clickhouse/client`, `@duckdb/node-api`, `node-firebird`, `surrealdb`, etc.) and from a Task 1.2 sweep for related-but-not-listed packages: AWS IAM auth (`@aws-sdk/credential-providers`, `@aws-sdk/rds-signer`, `@smithy/shared-ini-file-loader`), Azure auth (`@azure/msal-node`), MongoDB Query Language wrapper (`@queryleaf/lib`), and devDependency type packages (`@aws-sdk/types`, `@types/mssql`, `@types/oracledb`).

2. **`@azure/msal-node` was *not* orphaned.** I had grep-tested for it earlier with a malformed pattern (`@azure/msal-node\|msal-node` — wrong rg alternation syntax) and saw zero matches. A correct grep finds usage in `apps/studio/src/lib/db/authentication/azure.ts`, which is already on the Task 1.3 delete list (inventory §5). Lesson: validate negative-result greps with a positive control.

3. **No telemetry packages exist in `package.json`.** PRD §5 says "all upstream Beekeeper telemetry / analytics call sites and the telemetry library itself are removed during the cleanse." Sweep for `posthog|sentry|mixpanel|segment|amplitude|datadog|telemetry|analytics` in deps and devDeps returns empty. If telemetry exists in the codebase it does so without a package — possibly via a hand-rolled HTTP call to a Beekeeper endpoint. Task 1.3 should re-run the call-site sweep (`rg "telemetry|analytics|usage.*event"` etc.) inside source files.

4. **Two transitive native modules dropped quietly.** `kerberos` and `mongodb-client-encryption` were not declared in `apps/studio/package.json`; they came in via `mssql` and `mongodb` respectively. With those parents gone, the transitives went too. The Task 0.1 install previously rebuilt all four (better-sqlite3 + kerberos + mongodb-client-encryption + os-dns-native); now it would rebuild only better-sqlite3 + os-dns-native (and os-dns-native may also have been transitive — to verify post-cleanse).

5. **`mock-aws-s3` (devDependency) was kept.** It's used for backup test fixtures. After Task 1.3 deletes the backup code, `mock-aws-s3` becomes orphaned — flag for Task 1.3 sweep, not 1.2.
