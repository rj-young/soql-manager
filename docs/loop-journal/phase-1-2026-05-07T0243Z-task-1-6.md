## Anything surprising

1. **Renaming the workspace broke `yarn workspace beekeeper-studio …`.** Predictable in retrospect — the workspace name is its `package.json:name`. Caught at the first build attempt when `yarn workspace beekeeper-studio build` returned `Unknown workspace "beekeeper-studio"`. Fixed by bulk-renaming the references in the **root** `package.json` scripts plus the live docs (PRD, brief, build-commands). Loop journals from earlier tasks intentionally left unchanged — they accurately document what commands worked at that point in time.

2. **The repository field in the root `package.json` still points at upstream.** I left it as-is for now (`git@github.com:beekeeper-studio/beekeeper-studio.git`). The fork's actual remote is `rj-young/soql-manager`. Updating the `repository` field is technically a Phase 1 rebrand surface but feels closer to "distribution / publishing metadata" — a follow-up rather than this task. Flagged for end-of-Phase-1 verification.

3. **The Electron utility-process `serviceName` was a small bonus surface.** It's used internally by Electron for telemetry attribution (`process.title` on some platforms) and in process listing. `BeekeeperUtility` → `SoqlManagerUtility` is cosmetic but visible in `ps`. No functional impact.

4. **Did NOT touch:**
   - `LICENSE` / `NOTICE` files (anti-goal §4 — GPLv3 attribution stays).
   - `apps/studio/public/icons/` (Phase 1.6 explicitly excludes icons).
   - `apps/studio/src/assets/styles/` (theming deferred).
   - The Vue `<title>` element in HTML templates (the BrowserWindow title from WindowBuilder takes precedence at runtime).
   - The Beekeeper-branded copyright headers in source files (`Copyright (c) 2015 The SQLECTRON Team, 2020 Beekeeper Studio team`) — those are GPL upstream attribution and stay.
   - Auto-update server URLs (no auto-update channel for SOQL Manager yet; Phase 3+ concern).
