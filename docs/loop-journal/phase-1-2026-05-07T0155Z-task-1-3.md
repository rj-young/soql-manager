## Anything surprising

1. **No telemetry packages, no telemetry call sites.** Sweep for `telemetry|posthog|sentry|mixpanel|segment|amplitude|datadog|google-analytics|track\(|usageEvent|trackEvent|navigator\.sendBeacon` returned **zero matches** in `apps/studio/src` and `apps/studio/src-commercial`. Beekeeper community edition genuinely has no built-in telemetry. PRD §5's "telemetry stripped in Phase 1" is a no-op for this fork. `installation_id` model is preserved (it's just an installation UUID; license code uses it, not analytics).

2. **Cascade of dangling-imports was much smaller than feared.** After Batch A (clients only), 25+ unresolved imports. After Batch B (backup / restore / auth / etc.), still ~10. After Batch C (cloud / ssh / SQL UI components), 6. After targeted refactors of CoreInterface, CoreTabs, ConnectionInterface, sidebar files, and the two licensing-related cloud stubs, build went green. The Vue codebase routes most of its interconnections through `src/components/{CoreInterface,CoreTabs,ConnectionInterface}.vue` and `src/store/index.ts` — fix those four and the rest of the dependency graph cleaned up automatically.

3. **`@queryleaf/lib` was Mongo-specific** (only imported by `mongodb.ts` cursor / driver). Confirms the Task 1.2 sweep — no surprises.

4. **`sql_tools.ts` had to be partially restored.** I deleted it in Batch B, then discovered two consumers (`TabQueryEditor.vue` and `lib/editor/CodeMirrorPlugins.ts`) needed four functions from it. Re-created with stub implementations: behavior degrades safely (queries returned unchanged from `deparameterizeQuery`; `canDeparameterize` returns true only when no params present). Phase 2 rebuilds query handling for SOQL anyway.

5. **`store/index.ts` had to absorb `entityFilter`.** It was the only inlinable function from the deleted `sql_tools.ts` that survives because it's about table-list filtering, not SQL parsing. Inlined as 18 lines in `store/index.ts` with a header comment crediting the cleanse.

6. **Cloud-related getters reduced to constants.** `workspace()`, `isCloud()`, `cloudClient()`, `workspaceEmail()` in `store/index.ts` previously dispatched into the deleted `credentials/` Vuex namespace. Now: `workspace()` always returns `LocalWorkspace`, others return `false`/`null`. The cloud workspace concept is gone; consumers see a perpetually-local app. Behavior matches Task 1.1 review intent ("we won't use it").

7. **Two "stub" files added inside `lib/cloud/`.** Required to keep `LicenseModule.ts` compiling (anti-goal §4 — Ultimate code, untouched). 20 lines total. Net cleanse impact: directory removed (≈25 files, thousands of lines) → directory replaced (2 files, 20 lines) — still a 99% reduction in cloud surface.

8. **CoreTabs.vue lost ~7 conditional tab-type branches** (shell, table-properties, table-builder, import-export-database, backup, restore, import-table). Tabs of those types were generated by deleted UI flows; with the flows gone, the branches are unreachable anyway. Tab system continues to support: query, table (read-only), plugin-shell, plugin-base.

9. **No baseline tsc improvement from this task — it's still red, just for different reasons.** Most of the 274 baseline tsc errors were *in* the files we deleted (clients/anywhere.ts, clients/cassandra.ts, clients/clickhouse.ts, etc.). Those errors are gone. New errors arise from the SOQL Manager type system not yet existing (e.g. ConnectionType union still includes deleted dialects). Phase 1 Task 1.5 will narrow the type system; tsc gets re-enabled at end-of-Phase-1 per PRD §7 amendments.
